Conditional acceptance

Accept only if the module owns semaphore acquisition, abort races, starting transition, invocation, runner wiring, exceptional terminalization, and exact permit cleanup. Reject a pass-through that merely forwards values to runSubagent.

Problem

Solution

Deepen launch coordination below both adapters; keep job tracking and deferred delivery in the background module and thrown-result restoration in extension registration.

  • • locality: lifecycle in one module

Broad candidate rejected

Do not create one registry for slash commands, palette entries, keyboard routing, help, and execution. Those adapters are intentionally asymmetric; a universal interface would be wide, optional-field-heavy, and shallow.

Concrete friction found

• Parser-only aliases are not reserved.

• Suggested /clear can be intercepted.

• PromptAction mixes transport and UI.

• CLI initial UI requests disappear.

• Compact argument hint is missing.

• Bash abort/help gap is separate.

Problem

Canonical names, hidden aliases, argument policy, and collision reservation are three sources of command knowledge with no direct test surface.

Solution

Deepen only the local slash language; keep runtime mutations in the controller and context-sensitive palette, keyboard, and help behavior in the view module.

Benefits / wins

  • • aliases reserve consistently
  • • unknown input passes through
  • • tests hit language interface
  • • UI locality survives
